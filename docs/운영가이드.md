# TS본부 운영 대시보드 — 운영 가이드

## 1. 접속 방법

대시보드는 **이 PC(서버)** 에서 Docker 컨테이너 3개로 돌아갑니다.

| 위치 | 주소 |
|---|---|
| 서버 PC 본인 | `http://localhost:8080` |
| 같은 사내망 동료 | `http://192.168.21.58:8080` 또는 `http://192.168.20.110:8080` |
| API 문서 | `http://localhost:8080/docs` |

### 동료가 접속하려면 (최초 1회)
서버 PC에서 **관리자 PowerShell** 로 방화벽 8080 인바운드 허용:
```powershell
New-NetFirewallRule -DisplayName "TS Dashboard 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```
그 뒤 동료는 브라우저에 위 IP 주소를 입력하면 됩니다.
(서버 PC의 IP는 `ipconfig` 로 확인. 유선/무선에 따라 달라짐)

### 서버 켜기 / 재시작
Docker Desktop 이 실행 중이어야 합니다. 프로젝트 폴더에서:
```powershell
$env:Path = "$env:LOCALAPPDATA\Programs\DockerDesktop\resources\bin;" + $env:Path
cd C:\Users\genoray1\Downloads\ts-ops-dashboard
docker compose up -d          # 시작 (이미 떠 있으면 아무 일 없음)
docker compose ps             # 상태 확인 (backend/db/web = running)
docker compose restart backend  # 백엔드만 재시작
docker compose down           # 전체 정지 (데이터는 유지됨)
```
PC를 재부팅해도 Docker Desktop 이 자동 시작되면 컨테이너도 살아납니다.
데이터는 `pgdata` 볼륨에 영구 저장됩니다.

## 2. 새 엑셀 올리기

### 방법 A — 대시보드에서 (권장)
1. 상단 탭 **[데이터 관리]** 클릭
2. **[파일 선택]** 또는 점선 영역으로 **끌어다 놓기** (여러 개 가능)
3. 자동으로 양식을 판별해 파싱·적재 → 처리 결과가 파일별로 표시됨
4. 화면이 자동 갱신됨. 같은 화면의 **업로드 이력** 에서 상태 확인·되돌리기 가능

지원 양식 (파일명·시트로 자동 판별):
- `TS본부_주간업무(YYYY년 N월 N주).xlsx` — 신 주간양식
- `*주간회의록*.xlsx` — 구 주간양식
- `TS본부_월간실적(YYYY년 NN월)*.xlsx` — 월간 실적
- `*AS접수처리대장*.xlsx` / `AS보고서 *_N월.xlsx` — D/M/K/부산 AS 대장

### 방법 B — 명령어
```powershell
curl.exe -F "file=@C:\경로\파일.xlsx" http://localhost:8080/api/ingest
```

### 방법 C — 구글 시트 연동 (엑셀 업로드 없이)
데이터 관리 탭 → **구글 시트 연동** 패널. 설정하면 시트 URL만 등록해 두고 **동기화** 버튼으로 가져옵니다.
서버가 시트를 .xlsx 로 내려받아 방법 A/B 와 똑같이 처리하므로, **시트 양식은 기존 엑셀 양식과 동일해야** 합니다.

**최초 설정 (서버에서 1회):**
1. Google Cloud Console → 새 프로젝트 → **API 및 서비스 → 라이브러리** 에서 **Google Drive API** 와 **Google Sheets API** 사용 설정
2. **API 및 서비스 → 사용자 인증 정보 → 서비스 계정 만들기** → 역할 없이 생성 → 키 → **JSON** 다운로드
3. 그 JSON 파일을 `ts-ops-dashboard/deploy/google-sa.json` 으로 저장
4. `.env` 에 `TSD_GOOGLE_SA_JSON=/deploy/google-sa.json` 추가 → `docker compose up -d backend`
5. 연동할 각 구글 시트를 열어 **공유** → JSON 안의 `client_email` (…@….iam.gserviceaccount.com) 을 **뷰어** 로 추가

**사용:** 데이터 관리 탭에서 시트 URL 붙여넣기 → 시트 추가 → 전체 동기화.
정기 자동 동기화가 필요하면 알려주세요 (스케줄러 추가).

### 버전·롤백
- 같은 기간(주차/월/AS 장비군)을 다시 올리면 **새 버전이 이전 버전을 대체**하고, 이전 버전은 이력으로 보관됩니다.
- 업로드 이력: `GET http://localhost:8080/api/batches`
- 잘못 올린 배치 되돌리기: `POST http://localhost:8080/api/batches/{batch_id}/rollback`

## 3. 접근 방식 (로그인 / 시크릿 주소)

`deploy/nginx.conf` 가 출처에 따라 다르게 동작합니다:

| 어디서 접속하나 | 동작 |
|---|---|
| 사내망(사설 IP) · Tailscale(100.64.0.0/10) | **로그인 없이** 바로 열람 |
| 그 외(공개 인터넷 터널 등) | Basic 인증 요구 (안전망) |

- 즉, **사무실에서는 로그인 없이**, **밖에서는 아래 Tailscale 주소로** 들어오면 로그인창 없이 열립니다.
- Basic 인증 계정은 `deploy/PASSWORD.txt` 에 있음 (혹시 공개 URL 을 쓰게 될 때만 사용).

## 4. 사무실 밖에서 보기 — Tailscale 시크릿 주소 (권장)

공개 인터넷에 노출하지 않고, **내 기기에서만 보이는 고정 주소** 를 만듭니다.

1. **서버 PC** 에 설치: `Downloads\tailscale-setup.exe` 실행 → 로그인(구글/MS 계정 등)
2. **폰·노트북** 에도 Tailscale 앱 설치 → **같은 계정** 으로 로그인
3. 서버 PC 주소 확인:
   ```powershell
   & "$env:ProgramFiles\Tailscale\tailscale.exe" ip -4
   ```
   → 예: `100.101.102.103` (이 주소는 안 바뀝니다 = 고정)
4. **어디서든** 브라우저에 `http://100.101.102.103:8080`
   - Tailscale 로그인된 기기에서만 라우팅됨 → 사실상 "나만 아는 주소"
   - 사내망 규칙에 100.64/10 이 포함돼 있어 **로그인창도 안 뜸**

> 더 편의를 원하면 Tailscale 설정에서 이 기기에 **MagicDNS 이름**(예: `dashboard-pc`)을 붙여
> `http://dashboard-pc:8080` 으로도 접속 가능.

### (선택) 공개 URL 이 꼭 필요하면
`cloudflared` 로 `https://<무작위>.trycloudflare.com` 을 띄울 수 있으나 재시작 시 주소가 바뀌고,
고정 공개 주소는 Cloudflare 계정+도메인이 필요합니다. 이 경우 Basic 인증(§3)이 자동 적용됩니다.
포트포워딩으로 8080 을 직접 인터넷에 여는 것은 하지 마세요.

## 5. 백업

```powershell
# DB 덤프
docker compose exec -T db pg_dump -U tsd tsd > backup_$(Get-Date -Format yyyyMMdd).sql
# 복원
Get-Content backup_YYYYMMDD.sql | docker compose exec -T db psql -U tsd tsd
```
원본 엑셀은 각 업로드 배치에 그대로 보관됩니다 (`upload_batch.source_blob`).
